# N-D PDE-System Lie Reduction and ML Reductor

Status: draft for written review
Date: 2026-08-21
Approved architecture: hybrid option C, explicitly approved by the user on 2026-08-21.

## 1. Purpose

This specification extends the current scalar `(1+1)` Lie symmetry engine into
a backend-neutral framework for systems with `p` independent variables, `q`
dependent fields, and `r` differential equations. The first executable slice
is generic multi-index jet/prolongation support plus composable one-generator
reduction. Differential completion, arbitrary `k`-subalgebra reduction, and
proof-oriented backend integration are represented in the same contract even
when the local fallback cannot execute them.

The framework also supplies a deterministic PDE reductor for the ML tracks.
It may rank symmetry-derived features, reductions, and data augmentations, but
an ML score is never a mathematical certificate. Every recommendation carries
the exact or backend evidence that produced it.

## 2. Scope and non-goals

### In scope

- Arbitrary finite multi-indices over an ordered list of independent variables.
- Multiple dependent fields and any equation count, including `r != q`.
- Explicit equations, implicit polynomial differential equations, inequations,
  parameter assumptions, and regular branch metadata.
- Point generators in canonical order
  `(xi^1,...,xi^p,phi^1,...,phi^q)`.
- Recursive and characteristic-form point prolongation.
- Branchwise determining equations and bounded local fallback searches.
- One-generator reductions that can be chained when a later generator descends.
- Reduction certificates with pullback, rank, guard, and normal-form evidence.
- Maple and REDUCE subprocess adapters with explicit unavailable/partial states.
- Deterministic fingerprints, checkpoints, resource limits, and replay metadata.
- Symmetry-aware ML prioritization and invariant-coordinate features.

### Explicit non-goals

- Claiming a complete Lie algebra from a finite polynomial ansatz window.
- Treating a SymPy solve result as differential completion.
- Treating formal differential-algebraic branch semantics as analytic existence,
  smoothness, convergence, or global solvability.
- Silently dividing by a coefficient, rank minor, initial, or separant.
- Treating Maple DifferentialThomas and DifferentialAlgebra as independent
  scientific oracles; they are two Maple routes.
- Claiming that the local Python fallback certifies arbitrary Navier--Stokes
  or singular systems.

## 3. Mathematical contract

### 3.1 Bundle and jets

Let `pi:E -> X`, with `dim(X)=p`, independent coordinates `x^i`, and `q`
dependent coordinates `u^a`. A multi-index is `J=(J_1,...,J_p)` in
`N^p`, with `|J|=sum_i J_i` and unit vector `e_i`. Jet coordinates are
`u^a_J`, for `|J| <= n`, and `u^a_0` is `u^a`.

The finite jet space is represented by the ordered coordinates
`(x^i,u^a_J)`. The implementation must enumerate each multi-index once;
mixed derivatives are identified by their commutative multi-index.

Total derivatives on the infinite formal jet algebra are

`D_i = partial_xi + sum_(a,J) u^a_(J+e_i) partial_(u^a_J)`.

The finite implementation is lazy: a derivative is created only when requested
and an order budget is enforced. Property tests must verify `[D_i,D_j]=0`
on every expression whose required order is available.

### 3.2 Differential systems and guards

A system is

`S = (F_1=0,...,F_r=0; G_1 != 0,...,G_s != 0; A)`,

where `A` is a set of parameter and domain assumptions. The differential ideal
generated by the equations is closed under all total derivatives. Inequations
are represented as saturation guards, not as comments. A branch must preserve
the equations, inequations, ranking, assumptions, and every recorded division.

The default semantics of a completion branch is formal and differential-
algebraic. It describes a regular differential chain or simple system and its
guards. It does not by itself assert an analytic solution exists. A result may
claim analytic or smooth consequences only when an independently supplied
theorem and hypotheses are recorded.

### 3.3 Rankings and branches

Every completion request specifies a deterministic differential ranking:
derivative order, field order, tie-break order, and differentiation compatibility.

`DifferentialBranch` contains:

- triangular equations and inequations;
- leaders, initials, separants, and parametric derivatives;
- ranking and branch assumptions;
- integrability/coherence metadata;
- source backend, version, options, and input hashes;
- formal semantic label and verification checks.

Branches are disjoint only when the backend supplies that guarantee and the
normalized guards can be checked. A branch-local symmetry is not automatically
a global symmetry. The conservative global algebra is the intersection of
branch algebras unless explicit gluing/permutation evidence is stored.

### 3.4 Point prolongation

A point generator is

`X = sum_i xi^i(x,u) partial_xi + sum_a phi^a(x,u) partial_ua`.

Its characteristic is `Q^a = phi^a - sum_i xi^i u^a_(e_i)`. The two required
equivalent prolongation forms are

`phi^a_J = D_J(Q^a) + sum_i xi^i u^a_(J+e_i)`,

and

`phi^a_(J+e_i) = D_i(phi^a_J) - sum_l u^a_(J+e_l) D_i(xi^l)`.

The implementation uses the recurrence for bounded computation and a test
implementation of the characteristic form for equivalence checks.

For each branch, determining equations are obtained by applying the prolonged
generator to every branch equation, reducing by the branch normal form, and
splitting over independent parametric derivatives. A bounded ansatz is labeled
as bounded evidence, never as completeness.

### 3.5 Subalgebra reduction

For `h=span(X_1,...,X_k)`, closure requires

`[X_s,X_t] = sum_v c_(st)^v X_v`.

On a selected constant-rank stratum, the projected coefficient matrix
`Xi=(xi_s^i)` must have rank `k`. Quotient variables `z^mu` satisfy
`X_s(z^mu)=0`. An invariant graph also satisfies the invariant-surface
conditions

`Q_s^a = phi_s^a - sum_i xi_s^i u^a_(e_i) = 0`.

Rank minors, denominators, and nonzero guards are part of the reduction map.
Rank-drop strata are separate reductions. For composable one-generator
reductions, a later generator must descend to the reduced system; a sufficient
Lie-algebra condition is `[X_1,X_2] in span(X_1)`, but the descended action and
the reduced equations must still be checked directly.

The local correctness claim is branchwise and local: on a regular formally
integrable constant-rank branch, with projectable action, valid quotient/slice,
compatible invariant-surface conditions, preserved guards, valid
reconstruction, and total-derivative-compatible pullback, invariant holonomic
solutions correspond to reduced profiles whose reconstructions remain in the
branch. Rank drops, global topology, lost guards, and analytic existence remain
outside this claim.

## 4. Canonical data model

The canonical Python model is backend-neutral. Expressions are SymPy objects
in the local implementation, but adapters serialize a normalized expression
language rather than leaking backend syntax into the core.

### 4.1 Public types

```text
JetSpace
  independent_variables: tuple[Symbol, ...]
  dependent_fields: tuple[Symbol, ...]
  max_order: int
  ranking: DifferentialRanking

DifferentialSystem
  jet_space: JetSpace
  equations: tuple[Expr, ...]
  inequations: tuple[Expr, ...]
  assumptions: tuple[Expr, ...]
  name: str

DifferentialBranch
  equations, inequations
  leaders, initials, separants, parametric_derivatives
  ranking, assumptions, semantic_scope
  backend_provenance, verification

PointGenerator
  xi: tuple[Expr, ...]       # length p
  phi: tuple[Expr, ...]      # length q

LieSubalgebra
  generators: tuple[PointGenerator, ...]
  structure_constants
  closure_status

ReductionMap
  generator_or_subalgebra
  quotient_variables
  invariant_dependent_coordinates
  invariant_surface_equations
  pullback_rules
  reconstruction_rules
  rank_guards, denominator_guards

ReducedSystem
  equations, inequations, assumptions
  source_branch_id, reduction_map

CompletionCertificate / ReductionCertificate
  schema_version, system_fingerprint, configuration_fingerprint
  status, branch_coverage, assumptions, divisions
  checks, residuals, provenance
```

### 4.2 Legacy adapter

The existing public API remains unchanged:

- `PDE.scalar_1plus1` remains available;
- `pde.x`, `pde.t`, `pde.u` remain available;
- `jet_sym(a,b)` remains available;
- legacy generators remain `(tau,xi,phi)`.

The adapter maps legacy `(tau,xi,phi)` to canonical
`xi=(xi,tau)` and `phi=(phi)`, and maps canonical jets back to the existing
`(a,b)` keys. Existing scalar modules remain executable until parity tests
demonstrate that migration is behavior-preserving.

## 5. Pipeline and certificates

The orchestrator has these phases:

1. Normalize the system and compute a mathematical-system fingerprint.
2. Request completion/decomposition, or create a clearly labeled bounded
   fallback branch.
3. Derive branchwise determining systems.
4. Construct candidate generators and verify their residuals.
5. Form a one-generator reduction map or reject it with a status and reason.
6. Pull back every reduced equation and invariant-surface condition.
7. Compute branch normal forms and exact residual checks where supported.
8. Emit a versioned certificate and an ML/reductor record.

`verified` requires complete requested branch coverage plus independent
normal-form or substitution checks. A backend response alone is insufficient.

Completion and reduction need not commute. The optional discrepancy check
compares the normal forms of both routes and records one of:

`commutes`, `sound-only`, `branch-mismatch`, `guard-mismatch`,
`missing-integrability`, `rank-singular`, `backend-unavailable`, `timeout`,
or `unverified`.

## 6. Backend protocol

### 6.1 Request

Each subprocess request contains:

```text
schema_version
system_fingerprint
variables, fields, equations, inequations
ranking, assumptions
task: completion | determining | normal_form | reduction
timeout_seconds, memory_limit_bytes
backend/package/version constraint
```

Each response contains normalized branches, unsolved conditions, leaders and
guards when available, assumptions/divisions, backend identity, input/output
hashes, captured diagnostics, and independent verification results.

### 6.2 Maple route

Maple DifferentialThomas/ThomasDecomposition is the primary mature completion
route. DifferentialThomas documentation describes triangular differential
decomposition, singular cases, `NormalForm`, and `ReducedForm`. Maple
PDEtools supplies determining-equation and invariant-solution operations;
`casesplit` and DifferentialAlgebra/RosenfeldGroebner supply branch-oriented
operations. `CheckResults`, `Display`, `LinearCombination`, normal forms, and
independent Python checks are provenance inputs, not an assumed portable proof
certificate.

Maple is unavailable on the current machine. All local Maple statuses are
`backend-unavailable` until a licensed, version-pinned runner executes.

### 6.3 REDUCE route

REDUCE is the independent secondary route. The official manual documents
APPLYSYM/LIEPDE for infinitesimal symmetry and similarity-variable work,
CRACK for overdetermined polynomially nonlinear differential systems, and
CDIFF/CDE for total derivatives and differential-equation geometry.

CRACK history/replay data is reproducibility evidence, not a formal proof of
branch exhaustiveness. REDUCE is unavailable on the current machine, so local
statuses are also `backend-unavailable`.

### 6.4 Status vocabulary

```text
verified              complete branch coverage and independent checks pass
branch-partial        only a subset of branches/conditions is resolved
backend-unavailable   executable, package, or license is unavailable
timeout               watchdog or resource limit was reached
unsupported            declared backend/core preconditions are not met
inconsistent           assumptions yield no regular branch
oracle-disagreement    independent routes/checkers disagree
error                 parse, runtime, or serialization failure
```

Legacy statuses such as `CERTIFIED`, `PARTIAL`, and `LATENT-ONLY` are retained
only in the legacy view and do not imply generic proof status.

## 7. Fast and memory-bounded execution

The hard process RSS policy is `1.8 GiB`, below the requested 2 GiB limit. The
orchestrator enforces:

- soft warning at `1.2 GiB`;
- hard memory watchdog at `1.8 GiB`;
- wall-clock timeout per phase and backend subprocess;
- maximum jet order and lazy jet creation;
- maximum branch count and ansatz degree;
- expression-node, expanded-term, and serialized-output limits;
- no unrestricted global `expand` or unbounded simplification;
- deterministic cache keys including system, ranking, assumptions, backend,
  version, and resource configuration.

On a cap hit, the result is downgraded with the phase, order, branch, and
observed resource recorded. The fallback must never emit `verified` merely
because an expression became small or an ansatz stabilized.

## 8. PDE reductor and ML boundary

The reductor consumes a normalized system fingerprint and returns ranked
candidate reductions with features such as derivative structure, equation
count, field count, known generator family, orbit rank, and prior benchmark
outcomes. The existing scalar corpus remains a benchmark and is not silently
reinterpreted as a generic-system training set.

The ML layer may prioritize expensive completion calls, suggest a candidate
generator family, or select invariant-coordinate features. It may not change
equations, suppress branches, or upgrade a certificate status. Training,
validation, and inference records include corpus version, model/configuration
hash, seed, feature schema, and the exact evidence record used for ranking.

## 9. Migration plan

Implementation is test-first and ordered as follows:

1. Add canonical types and legacy adapter without changing scalar behavior.
2. Add multi-index enumeration, lazy total derivatives, and generic
   characteristic/recursive prolongation.
3. Add generic determining-system construction and bounded ansatz controls.
4. Add Lie brackets, closure, subalgebra metadata, and descended generators.
5. Add completion/normal-form interchange and Maple/REDUCE adapter schemas.
6. Add one-generator pullback/reconstruction and certificates.
7. Migrate checkpointing, reports, CLI, and reductor consumers with schema
   versioning.
8. Add corpus, hard-system structural checks, and backend parity harness.
9. Add the advanced `intro.tex` section and compile/document verification.

No existing scalar module is removed until its compatibility tests and the
full baseline pass.

## 10. Validation corpus and acceptance gates

### Existing gates

- All current scalar tests remain green, currently 45 collected.
- Textbook scalar table remains 6/6, including explicit infinite-dimensional
  `stalled` handling.
- Existing reductor benchmark remains reproducible and its weak high-symmetry
  recall remains visible.

### Generic property gates

- multi-index count and canonical renaming;
- commuting total derivatives;
- recursive/characteristic prolongation equivalence;
- bracket antisymmetry and Jacobi identity;
- field and independent-variable permutation covariance;
- legacy adapter equivalence.

### System gates

1. Scalar `2+1` heat equation.
2. Two-field reaction-diffusion system with `(p,q,r)=(3,2,2)`.
3. Cauchy--Riemann system `(2,2,2)`.
4. An over/underdetermined constraint with `r != q`.
5. Parameter branch `a*u_t-u_x=0`, preserving `a=0` and `a!=0` cases.
6. Rank-dropping rotational reduction with separate singular stratum.
7. Composable translations reducing `p -> p-1 -> p-2`.
8. Incompressible 2D Navier--Stokes `(3,3,3)`:

   `F1=u_t+u*u_x+v*u_y+p_x-nu*(u_xx+u_yy)`

   `F2=v_t+u*v_x+v*v_y+p_y-nu*(v_xx+v_yy)`

   `F3=u_x+v_y`

The local fallback may return `unsupported`, `backend-unavailable`, or
`timeout` on Navier--Stokes. Such a result is a pass only for the honest
status gate, not a claim of complete symmetry discovery.

Every emitted reduction requires invariant-surface, pullback, and branch
normal-form checks. Negative controls include hidden integrability conditions,
lost inequations, rank drops, incompatible invariant surfaces, and divisions
by zero factors.
