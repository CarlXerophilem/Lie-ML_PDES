  what's happening underneath, built up from the start.

  The one-line version

  A Lie algebra is a variable-compression tool: each independent generator is a
  direction along which the PDE looks identical to itself, and every such
  direction lets you delete one variable by switching to coordinates that don't
  change along it. Fisher lives in (x, t) — two independent variables — so using
  one symmetry direction drops you to one variable z, i.e. PDE → ODE. That
  reduced ODE is exactly what the rest of the pipeline (HAM series → certificate
  → PINN) then consumes.

  What one generator actually is

  A generator is a vector field X = τ ∂_t + ξ ∂_x + φ ∂_u — an infinitesimal
  recipe for nudging (t, x, u). It "is a symmetry" when nudging any solution
  gives you another solution. That condition, run through the prolongation
  formula, is the residual our engine checks: for Fisher, ∂_t (τ=1) and ∂_x
  (ξ=1) both gave residual 0 above, so both are genuine symmetries.

  The key move is that a symmetry has invariants — quantities the nudge leaves
  fixed. You find them by solving the characteristic system

  dx/ξ  =  dt/τ  =  du/φ .

  For the travelling-wave combination X = ∂_t + c ∂_x (τ=1, ξ=c, φ=0):
  - du/0 says u itself is unchanged → the profile U,
  - dx/c = dt/1 integrates to x − c t = const → the similarity variable z.

  So "a solution that respects this symmetry" must have the form u(x,t) = U(z).
  Substitute that in and the two-variable derivatives collapse (u_t = −cU′, u_xx
  = U″), leaving the ODE you saw. That collapse is the compression — the
  symmetry guaranteed the answer only depends on z, so x and t separately never
  appear again.

  What the algebra buys you beyond one generator

  This is where "algebra" (not just "a symmetry") earns its name. The full set
  of generators is a vector space — you can add and scale them — and it's closed
  under the bracket [X, Y] = XY − YX. Two things follow, and they're exactly
  the two things our engine measures:

  (1) The dimension = how much reduction is on the menu. This is the number we
  validated in G1: Fisher 2, Burgers 5, porous 4, KdV 4. A bigger algebra means
  more inequivalent ways to reduce (each different subalgebra gives a different
  similarity variable and a different ODE). Fisher's 2-dimensional algebra is
  small — essentially it offers the travelling-wave reduction. Burgers'
  5-dimensional algebra is large, which is the fingerprint of it being
  linearizable (Cole–Hopf); porous medium's 4 includes scaling generators, which
  is why it has self-similar Barenblatt solutions.

  (2) The bracket structure = whether you can keep reducing. After you reduce by
  one generator X, the other symmetries don't vanish — the ones compatible with
  X (its normalizer) descend to become symmetries of the reduced ODE. If the
  algebra is solvable, you can peel them off one at a time, each one integrating
  the ODE down by one order, until you reach an explicit answer — this is Lie's
  theorem, the deep reason "enough symmetry ⇒ integrable by quadratures."
  Concretely for Fisher: after the reduction, the ODE U″ + cU′ + U(1−U) = 0
  still has a leftover z-translation symmetry, and that is what lets you drop it
  into the 2-D (U, U′) phase plane — the standard way Fisher travelling fronts
  are analyzed. algebra.py computes these brackets and the derived/lower-central
  series precisely to report solvable-vs-not.

  The two reduction "branches" in our engine

  reduce.py implements exactly the two most common generator types:
  - Translation branch → travelling waves, z = x − ct, u = U(z) (the Fisher case
  above). Derivatives just pick up powers of −c.
  - Scaling branch → self-similar solutions, z = x / t^a, u = t^b U(z) (the
  porous-medium/Barenblatt case). Here u does transform (φ ≠ 0), so the profile
  carries a t-power out front.

  Which branch fires is dictated by which generator you hand it — the algebra is
  the menu, each generator (or low-dimensional subalgebra) is a dish, and the
  guards in the code (e.g. the projective generator returning None) are there
  because some generators don't yield a clean lower-order ODE through this
  simple ansatz.

  The infinite case, connected to G1

  When the algebra is infinite-dimensional — heat and transport, which G1
  flagged as stalled — the "compression" is of a different flavor. A linear PDE
  always contains the superposition symmetry u → u + β for any other solution β,
  which is an infinite family of generators. That infinitude is just linearity
  restated as symmetry: you can't compress two variables to one and stop,
  because there are infinitely many independent symmetry directions. The engine
  correctly refuses to report a finite dimension there — which is exactly the
  honest behavior we validated.

  How it all chains in CCS-SYM+

  So the algebra's job in the pipeline is narrow and precise: REDUCE uses it to
  manufacture a faithful low-dimensional ODE whose solutions are exactly the
  symmetric solutions of the PDE; the dimension tells you the reduction exists
  and the structure tells you how far it can go; then CLOSE/CERTIFY/CORRECT work
  entirely on that ODE. Everything downstream inherits its trustworthiness from
  this step being an exact algebraic fact, not an approximation.
