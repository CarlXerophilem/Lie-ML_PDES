# N-D PDE-System Lie Reduction Implementation Plan

Spec: `docs/superpowers/specs/2026-07-30-nd-pde-system-lie-reduction-design.md`
Status: approved for implementation
Date: 2026-08-22

## Constraints

- Preserve all existing scalar `(1+1)` APIs and tests.
- Keep generic code in a new package; do not rewrite legacy modules during the
  first migration slice.
- Use only the current Python/SymPy/NumPy/pytest environment for the local
  fallback.
- Do not report a bounded ansatz as a complete algebra or a no-op completion as
  a differential decomposition.
- Enforce a 1.8 GiB hard RSS policy and explicit order/branch/expression caps.
- Use ASCII-only source and UTF-8 for documentation.

## Ordered tasks

### T1. Canonical IR and persistence metadata

Create `symm/generic/` with dataclasses for `JetSpace`, `DifferentialSystem`,
`DifferentialBranch`, `PointGenerator`, `LieSubalgebra`, `ReductionMap`,
`ReducedSystem`, `CompletionCertificate`, and `ReductionCertificate`.

Acceptance:

- immutable/canonical tuples where appropriate;
- validation of `(p,q,r)`, multi-index lengths, generator lengths, and empty
  equation/guard collections;
- deterministic `system_fingerprint` and `configuration_fingerprint`;
- explicit statuses from the specification;
- JSON-safe summary/provenance without serializing executable objects.

### T2. Generic jets and prolongation

Implement multi-index enumeration, lazy jet naming, total derivatives, and
point prolongation. Implement both the recurrence and characteristic formulas
behind the same public API.

Acceptance:

- exact jet count `q * binomial(p+n,n)`;
- total derivative commutation on expressions within the order budget;
- recurrence/characteristic equality for scalar and multi-field examples;
- permutation/renaming covariance;
- expression and order caps fail with an explicit `unsupported` status or
  bounded exception, never silent truncation.

### T3. Algebra and reduction kernel

Implement generator brackets, closure checks, projected orbit rank, and a
composable one-generator translation reduction. The first automatic reduction
supports a generator translating one independent coordinate with zero dependent
component. A general `ReductionMap` remains constructible for future quotient
solvers.

Acceptance:

- bracket antisymmetry and Jacobi tests;
- translation reduction maps `p` independent variables to `p-1`;
- derivative pullback rules are exact for all requested jet orders;
- invariant-surface equations, rank guards, and denominator guards are retained;
- a second compatible translation can be applied to the reduced system;
- every reduction emits a certificate and exact residual checks.

### T4. Completion and backend boundary

Implement a bounded local branch wrapper and backend request/response schema.
The local wrapper preserves the original system and reports
`unsupported`/`branch-partial` rather than pretending completion occurred.
Backend availability is detected without importing vendor-specific syntax.

Acceptance:

- branch records retain equations, inequations, assumptions, ranking, and
  provenance;
- parameter singular and lost-inequation negatives are represented without
  illegal division;
- unavailable Maple/REDUCE produces a structured status;
- cache keys include system, ranking, assumptions, backend, and limits.

### T5. PDE reductor and hard benchmark registry

Implement a deterministic `PDEsReductor` that ranks candidate reductions and
ML features but cannot upgrade certificate status. Add scalar adapters, a
two-field reaction-diffusion example, Cauchy--Riemann, an `r != q` constraint,
and incompressible 2D Navier--Stokes.

Acceptance:

- existing scalar corpus remains usable;
- reductor records feature schema, evidence, status, and score rationale;
- Navier--Stokes structural construction validates `(3,3,3)`, equations, and
  known translation/pressure-gauge/Galilean residuals where implemented;
- unsupported full symmetry discovery is explicitly reported.

### T6. Tests and migration checks

Add focused tests only for the new package. Run the full existing suite after
each major task. Tests cover positive properties and negative controls:
incompatible invariant surfaces, rank drop, zero division guard, branch
coverage, unsupported backend, and resource cap.

Acceptance:

- legacy suite remains green;
- new generic tests are deterministic and no random seed is required unless
  explicitly recorded;
- test output records the known Python site-package warning without treating it
  as a test failure;
- no generated bytecode or benchmark output is required for correctness.

### T7. Resource and benchmark verification

Run the existing textbook and scalar reductor benchmarks, generic property
tests, the hard-system registry, and a traced-memory smoke test. Record actual
commands and outcomes. Compile `intro.tex` only after code behavior is stable.

Acceptance:

- current scalar benchmark remains 6/6;
- existing reductor metrics are reproduced or discrepancies are recorded;
- hard system either passes structural checks or reports an honest unsupported
  status;
- traced RSS and subprocess limits remain below 1.8 GiB;
- all unsupported backend claims remain clearly separated from verified local
  algebraic checks.

## File ownership

Initial implementation writes are limited to:

- `symm/generic/*.py`;
- `symm/tests/test_generic_*.py`;
- `docs/superpowers/plans/2026-08-22-nd-pde-system-lie-reduction.md`;
- later, the approved `intro.tex` section and benchmark documentation.

Legacy `symm/sym_engine/*.py` files are read-only during T1--T6 unless a
separate parity defect is demonstrated and reviewed.
